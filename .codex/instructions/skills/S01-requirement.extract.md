# 技能：需求提取

## Meta
- DependsOn:
- Category: requirement
- Status: stable

## 一句话描述
从用户描述、设计文档、原型页面和运行态 DOM 中，提取结构化需求文档。

## 输入
- `raw_text`：string（用户的项目描述）
- `prototype_dir`：可选，默认 `原型/`
- `design_docs`：可选，默认读取项目内已提供的设计说明、架构图说明或相关 Markdown 文档

## 输出
- `docs/skill-chain/requirements.md`：结构化需求文档（中文 Markdown）

## Prompt

你是一位资深产品分析师与系统架构师。
请根据用户输入、设计文档、原型静态文件与原型运行态 DOM，完成以下工作：

0. **输入发现与原型提取**：
   - 如果存在 `原型/` 目录，必须逐个读取目录下所有 `.html` 页面，不得只依据用户描述或设计文档生成需求。
   - 对每个 HTML 页面，必须提取页面标题、导航菜单、Tab、按钮、表单字段、表格列、弹窗/抽屉/面板、主要容器、JS 函数名、事件绑定、mock 数据结构。
   - 必须优先使用 Playwright 无头浏览器打开原型页，执行页面 JS，并提取 `document.body.innerText` 与关键 DOM 节点文本；关键 DOM 节点至少覆盖 `nav`、`aside`、`header`、`main`、`section`、`form`、`table`、`dialog`、`.modal`、`.drawer`、`.tab`、`.tabs`、`.panel`、`.card`、`.toolbar`。
   - Playwright 提取失败时，必须降级为静态 HTML 解析，并在文档中标记“Playwright 提取失败，已使用静态解析”。
   - 如果不存在原型目录或没有 HTML 原型，必须降级为从 `raw_text`、设计文档和可用资料中提取需求，并在文档中增加“原型缺失说明”，列出缺失影响与待确认项。
   - 不允许因为没有原型而中止 S1；只有在 `raw_text`、设计文档和原型均不足以识别项目目标时，才输出 Skill Issue Report。

1. **项目类型识别**：判断属于以下哪类
   - 传统 Web 项目（管理系统、电商、社交等）
   - AI 项目（LLM / RAG / Agent / 多模态 / 语义搜索）
   - 混合项目（传统业务 + AI 增强）

2. **提取用户角色（User Roles）**，表格形式：
   | 角色 | 描述 | 核心诉求 |
   |------|------|----------|

3. **提取核心功能（Core Features）**，表格形式：
   | 功能模块 | 功能描述 | 优先级 |
   |----------|----------|--------|

4. **提取非功能需求（Non-Functional Requirements）**：
   | 维度 | 要求 | 说明 |
   |------|------|------|
   | 性能 | ... | ... |
   | 安全 | ... | ... |
   | 可扩展性 | ... | ... |
   | 可用性 | ... | ... |

5. **AI 特征识别**（如适用）：
   | AI 能力 | 用途 | 技术方向 |
   |----------|------|----------|
   | LLM 对话 | ... | ... |
   | RAG 检索 | ... | ... |
   | 向量搜索 | ... | ... |
   | Agent 编排 | ... | ... |
   | BERT 文本分析 | ... | ... |

6. **项目规模评估**：
   - 团队规模预估
   - 开发周期预估
   - 技术复杂度评级

7. **页面功能清单**：
   | 页面 | 页面目标 | 核心区域 | 用户操作 | 数据对象 | 权限要求 |
   |------|----------|----------|----------|----------|----------|

8. **交互行为清单**：
   | 交互 | 触发方式 | 系统响应 | 涉及页面 | 优先级 |
   |------|----------|----------|----------|--------|

9. **数据对象识别**：
   | 数据对象 | 关键字段 | 来源页面 | 说明 |
   |----------|----------|----------|------|

10. **隐含后端能力推导**：
   | 后端能力 | 依据 | 来源类型 | 确认状态 |
   |----------|------|----------|----------|

   `来源类型` 只能使用：
   - 明确需求
   - 原型推导
   - 待确认

11. **原型覆盖检查**：
   | 原型页面 | 是否已读取 | 是否已提取 | 缺口 |
   |----------|------------|------------|------|

12. **原型缺失说明**（仅无原型时输出）：
   | 缺失项 | 影响 | 后续确认方式 |
   |--------|------|--------------|

## 行为规则

- ✅ 必须输出中文 Markdown 表格
- ✅ 不确定项标记为 "待确认"
- ✅ AI 项目必须识别 AI 特征表
- ✅ 存在 `原型/` 时，必须输出“页面功能清单、交互行为清单、数据对象识别、隐含后端能力推导、原型覆盖检查”
- ✅ Playwright 可用时必须使用无头浏览器提取运行态 DOM 文本；不可用或失败时必须说明降级原因
- ✅ 没有原型时必须输出“原型缺失说明”，并继续基于可用输入提取需求
- ❌ 不得编造不存在的需求
- ❌ 不得遗漏用户明确提到的功能
- ❌ 不得遗漏任一已发现 HTML 原型页面
- ❌ 不得把“原型推导”的内容写成“明确需求”
