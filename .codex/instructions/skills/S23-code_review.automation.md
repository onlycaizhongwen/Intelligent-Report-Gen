# 技能：代码审查自动化

## Meta
- DependsOn: S14, S16, S17
- Category: quality
- Status: stable

## 一句话描述
自动审查代码质量，输出审查报告。

## 输入
- `backend/`：DDD 后端代码目录
- `pages/`（前端页面代码）
- `components/`（组件代码）
- `openspec/specs/`：OpenSpec capability 目录

## 输出
- `docs/skill-chain/review_report.md`：代码审查报告（中文 Markdown）

## Prompt

你是一位资深代码审查专家。
请对以下维度进行自动审查，输出报告。

代码审查必须包含 OpenSpec 偏离检查：实现、页面、组件和测试不得偏离 frozen baseline。

### 审查维度

1. **代码规范**：

   | 检查项 | 说明 | 严重程度 |
   |--------|------|----------|
   | 命名规范 | 变量/函数/类名是否符合规范 | 🟡 低 |
   | 注释覆盖率 | 关键逻辑是否有中文注释 | 🟡 低 |
   | 代码长度 | 单个函数不超过 80 行 | 🟢 建议 |
   | 重复代码 | 是否有可提取的公共逻辑 | 🟡 低 |

2. **安全审查**：

   | 检查项 | 说明 | 严重程度 |
   |--------|------|----------|
   | SQL 注入 | 是否使用参数化查询 | 🔴 高 |
   | XSS 防护 | 用户输入是否转义 | 🔴 高 |
   | 密码存储 | 是否 BCrypt 加密 | 🔴 高 |
   | Token 处理 | 是否 HttpOnly / HTTPS | 🔴 高 |
   | Prompt 注入（AI 项目） | 用户输入是否过滤 | 🔴 高 |
   | 敏感信息泄露 | 日志/响应中是否含敏感数据 | 🔴 高 |

3. **性能审查**：

   | 检查项 | 说明 | 严重程度 |
   |--------|------|----------|
   | N+1 查询 | 是否在循环中查数据库 | 🟡 低 |
   | 大结果集 | 是否分页 / 限制返回量 | 🟡 低 |
   | 缓存缺失 | 热点数据是否未缓存 | 🟡 低 |
   | AI 超时 | LLM 调用是否有超时 | 🔴 高 |
   | Token 浪费 | 是否发送不必要的长上下文 | 🟡 低 |

4. **架构审查**：

   | 检查项 | 说明 | 严重程度 |
   |--------|------|----------|
   | 分层违规 | Controller 是否包含业务逻辑 | 🔴 高 |
   | 职责混乱 | 一个类是否做太多事 | 🟡 低 |
   | 依赖方向 | 是否出现循环依赖 | 🔴 高 |
   | 组件耦合 | 组件是否直接调用 API | 🟡 低 |

5. **AI 项目专项审查**：

   | 检查项 | 说明 | 严重程度 |
   |--------|------|----------|
   | RAG 流程 | 检索 → 增强 → 生成是否完整 | 🔴 高 |
   | Embedding 缓存 | 相同文本是否重复编码 | 🟡 低 |
   | 流式处理 | 前端是否正确消费 SSE 流 | 🔴 高 |
   | 降级策略 | AI 服务不可用时是否有降级 | 🟡 低 |
   | Token 计费 | 是否记录和限制 Token 用量 | 🟡 低 |

### 报告格式

```markdown
# 代码审查报告

## 概要
- 审查时间：2024-01-01 12:00:00
- 审查文件数：XX
- 🔴 严重问题：X 个（必须修复）
- 🟡 一般问题：X 个（建议修复）
- 🟢 优化建议：X 个（可选）

## 🔴 严重问题（必须修复）

### [S14] DocumentServiceImpl.java:45
- **问题**：SQL 拼接，存在注入风险
- **代码**：`String sql = "SELECT * FROM documents WHERE title = '" + title + "'";`
- **建议**：使用 `PreparedStatement` 或 ORM

### [S14] ChatService.py:78
- **问题**：LLM 调用未设置超时
- **建议**：添加 `timeout=30` 参数

## 🟡 一般问题（建议修复）

### [S17] ChatInput.tsx:23
- **问题**：组件直接调用 API，未通过 Store
- **建议**：将 API 调用移到 Store 中

## 🟢 优化建议

### [S14] DocumentService.java:112
- **建议**：文件解析逻辑可提取为独立类
```

## 行为规则

- ✅ 必须给出具体的文件名和行号
- ✅ 必须有代码片段 + 修复建议
- ✅ 必须检查实现是否偏离 OpenSpec requirement / scenario
- ✅ AI 项目必须审查 RAG 流程和 Prompt 安全
- ✅ 严重程度分级（🔴/🟡/🟢）
- ✅ 报告必须是中文 Markdown
- ❌ 不得忽略安全问题
- ❌ 不得只给结论不给建议
