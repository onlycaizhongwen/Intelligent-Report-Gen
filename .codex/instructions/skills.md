# Skill 索引目录

## 使用方式

在 Codex 对话中输入：
```
加载 <skill id="S1">，开始全栈项目开发
```

或指定多个 Skill：
```
依次加载 <skill id="S1">、<skill id="S2">、<skill id="S3">，完成需求分析与建模
```

## 执行顺序

# 最高优先级规则
- 在执行链中，每完成一个里程碑（S1, S2...S7），必须暂停并等待用户明确批准。
- 绝对禁止自动跳过 S1-S7 进入 S8。

# 架构图规则
- 所有架构图、技术栈图、模块关系图、服务拓扑图、数据流图必须使用 Mermaid。
- 禁止 ASCII 方框图、纯文本箭头图或非 Mermaid 图。

# 文档产物目录规则
- 除 OpenSpec 外，所有 Skill 生成的 Markdown 文档必须统一输出到 `docs/skill-chain/`。
- `openspec/` 独立存放规格文件；源码、测试、配置、迁移、监控按工程结构输出。

按 registry.yaml 中的 depends_on 顺序执行，关键检查点：
- S1 完成后：必须暂停，等待用户明确回复 `APPROVED` 或“批准”后才可进入 S2
- S2 完成后：必须暂停，等待用户明确回复 `APPROVED` 或“批准”后才可进入 S3
- S3 完成后：领域模型与 OpenSpec capability 草案必须暂停，等待用户明确回复 `APPROVED` 或“批准”后才可进入 S4
- S4 完成后：API 契约与 OpenSpec change/delta 必须暂停，等待用户明确回复 `APPROVED` 或“批准”后才可进入 S5
- S5 完成后：必须暂停，等待用户明确回复 `APPROVED` 或“批准”后才可进入 S6
- S6 完成后：必须暂停，等待用户明确回复 `APPROVED` 或“批准”后才可进入 S7
- S7 完成后：服务边界与 OpenSpec capability 映射必须暂停，等待用户明确回复 `APPROVED` 或“批准”后才可进入 S8；S7 获批后 OpenSpec baseline 冻结，未批准前绝对禁止进入 S8
- S12 完成后：后端接口可调用
- S20 完成后：前后端契约一致
- S23 完成后：代码质量达标
- S27 完成后：可部署上线
