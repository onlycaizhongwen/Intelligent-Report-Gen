> Skill：S1 requirement.extract  
> 来源：`prompt.md`、`原型/design-doc.md`、`原型/*.html`、`资料/业务架构图.png`、`资料/系统架构图.png`

## 1. 项目定位

智能报告生成系统是一个“传统业务管理系统 + AI 增强”的混合项目。核心目标是：基于企业知识库、企业数据源和线上 GPT 模型，生成可溯源、可审计、可导出、可协作的智能报告。

当前范围包含：

- 报告中心：智能生成、模板填报、我的报告、历史记录。
- 管理中心：知识库管理、工作台仪表盘、规则引擎、用户权限与协作。
- AI 能力：RAG 检索、线上 GPT 生成、流式输出、引用溯源、引用质量评估、模型调用审计。
- 基础设施：Java 业务核心、Python AI 服务、PostgreSQL、RocketMQ、MinIO、Milvus、OpenSearch、Higress。

明确不纳入当前阶段：

- 多租户。
- 私有化部署。
- 高可用和灾备。
- 报告人工审核发布流程。
- 本地 GPU/vLLM 推理。

## 2. 用户角色

| 角色 | 描述 | 核心诉求 |
| --- | --- | --- |
| 业务分析师 | 日常生成分析报告，偏好自然语言输入 | 快速生成报告、查看溯源、导出成果 |
| 管理人员 | 关注周期性报告和经营概览 | 通过模板和参数生成标准化报告，查看仪表盘 |
| 管理员 | 系统管理与配置角色 | 管理用户、权限、知识库、数据源、规则和审计 |
| 高级分析师 | 具备较高业务和知识库权限 | 创建、编辑、分享报告，维护部分知识和数据源 |
| 分析师 | 常规报告生产角色 | 创建、查看、分享、批注、导出授权报告 |
| 查看者 | 只读或轻协作角色 | 查看报告、查看引用、批注、导出授权内容 |
| 业务人员 | 提供和复用业务资料 | 查询知识库、上传资料、反馈业务事实 |
| 外部协作用户 | 通过分享链接访问报告 | 输入凭证后受控查看报告并提交反馈 |

## 4. 核心功能需求

### 4.1 报告生成

- 用户可以通过自然语言描述报告主题、时间范围、分析维度和重点关注。
- 用户可以选择模板，填写周期、对象范围、关注重点和报告风格。
- 系统必须先生成大纲，用户确认或修改后才进入正文生成。
- 系统必须展示“检索知识库、分析数据、生成报告”三个阶段进度。
- 报告正文必须支持逐段流式可见。
- 生成结果必须保存为报告，并产生版本记录和审计记录。

### 4.2 溯源与导出

- 报告正文引用标记和右侧来源列表必须双向定位。
- 来源必须展示来源库、来源名称、来源类型、摘要、快照和可信度评分或质量标签。
- 导出必须支持 PDF、Word、PPT、Markdown。
- 导出必须应用企业模板、目录、页眉页脚、Logo、字体、颜色等品牌规范。
- 导出结果必须提供下载地址，并记录导出日志。

### 4.3 知识库与数据源

- 知识库支持预置库和自定义库。
- 知识条目支持搜索、筛选、分页、查看、更新和删除。
- 删除被报告引用的知识条目时必须提示影响并要求确认。
- 手动录入必须包含标题、所属知识库、内容类型、标签和内容。
- 文件上传必须进入 Java 业务核心，由 Java 保存元数据和对象存储，再通过 RocketMQ 解耦给 Python AI 服务解析。
- Python AI 服务必须完成 OCR、图片表格识别、扫描件解析、分块、索引和失败原因记录。
- 企业数据源必须支持测试连接、保存配置、同步策略、同步状态和同步异常记录。

### 4.4 规则引擎

- 管理员可以创建规则、从模板创建、导入、保存和运行规则。
- 规则画布支持节点拖拽、连线、节点参数配置、连线合法性校验。
- 调试面板支持执行调试、单步执行、清空日志。
- 调试日志必须记录节点输入、输出、状态、耗时和错误信息。

### 4.5 用户、权限、协作和审计

- RBAC 当前至少包含管理员、高级分析师、分析师、查看者。
- 用户管理支持添加、批量导入、筛选角色、编辑、启用和禁用。
- 分享链接必须支持访问密码、有效期、撤销、外部访问和访问日志。
- 批注必须绑定报告文本位置，支持指派处理人、状态流转和站内通知。
- 普通用户只能查看个人历史，管理员可以查看全局审计日志。
- Prompt、检索上下文、生成过程、模型调用参数、模型响应、耗时和结果必须完整审计。

## 5. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 安全 | 统一身份认证，RBAC 权限控制，外部分享受控访问 |
| 审计 | 关键写操作、模型调用、生成过程、导出、分享必须可追踪 |
| 可用性 | 长耗时 AI 过程必须流式反馈，失败必须可见且可重试 |
| 可扩展性 | AI 模型、数据源类型、知识库类型、规则节点必须可扩展 |
| 可维护性 | 后端按 DDD 分层，前端按页面/组件/API 分层，文档集中在 `docs/skill-chain/` |
| 本地开发 | 优先 Docker Compose，一键拉起依赖，不连接生产数据库 |
