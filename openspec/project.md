# 智能报告生成系统 OpenSpec 项目说明

## 目标

智能报告生成系统 SHALL 支持用户基于自然语言或模板填报生成可溯源、可导出、可协作、可审计的企业报告。

系统 SHALL 将知识库、RAG 检索、线上 GPT 调用、引用锚定、权限协作和操作审计纳入统一需求约束，确保后续 API、架构、代码和测试均可追溯到本规格。

## 范围

| 范围 | 说明 |
| --- | --- |
| 报告生成 | 自然语言生成、模板填报、大纲确认、三阶段流式生成 |
| 溯源引用 | 引用锚点、来源快照、证据可信度评分、引用质量评估 |
| 报告交付 | PDF、Word、PPT、Markdown 导出，以及版式、模板、目录、页眉页脚、企业品牌规范 |
| 知识库 | 知识库、知识条目、文件解析、OCR、图片表格识别、扫描件处理 |
| 数据源 | 企业内部数据库、ERP、OA、财务系统、API、定时拉取 |
| 规则解析 | 可视化规则编排、节点参数、连线、调试执行、节点日志 |
| 权限协作 | RBAC、分享链接、外部用户访问、访问密码、有效期、批注、任务、站内通知 |
| 审计历史 | 个人历史、管理员操作日志、Prompt 审计、生成过程审计、模型调用审计 |
| 工作台 | 指标卡片、报告趋势、知识库引用排行、最近活动 |

## 非目标

系统 SHALL NOT 在当前范围内引入多租户、私有化部署、高可用、灾备或报告人工审核发布流程。

历史记录中出现的“审核”样例 SHALL 仅作为历史数据样例处理，不得被解释为当前报告审批发布需求。

## 术语

| 术语 | 定义 |
| --- | --- |
| 报告 | 用户生成、查看、导出、分享和版本管理的核心业务对象 |
| 报告生成任务 | 一次自然语言或模板填报生成报告的执行过程 |
| 报告大纲 | 报告正文生成前由 AI 生成并由用户确认的结构 |
| 知识库 | 存放规则、财报、法规、调研和自定义知识的集合 |
| 知识条目 | 可被检索、引用和管理的知识内容 |
| 知识文档 | 上传文件或数据源同步形成的原始解析文档 |
| RAG | 从知识库检索、重排序和压缩上下文后辅助模型生成的过程 |
| 引用锚点 | 报告正文中定位到知识来源的标记 |
| 证据评分 | 对引用来源相关性、时效性、权威性和覆盖度的质量评价 |
| 规则 | 用于知识入库解析或业务文本处理的可视化流程 |
| RBAC | 基于角色的访问控制模型 |
| 分享链接 | 带密码、有效期、撤销状态和访问日志的外部访问入口 |
| 批注任务 | 围绕报告文本片段产生的评论、指派和处理状态 |
| 操作日志 | 系统记录的关键行为审计事件 |
| 模型调用记录 | 记录 Prompt、上下文、参数、响应、耗时和结果的 AI 调用审计对象 |

## 技术边界

- Java 业务核心 SHALL 作为外部业务 API 的统一入口，承担 RBAC、任务状态、持久化和审计闭环。
- Python AI 服务 SHALL 作为内部 AI 执行面，支持 RocketMQ 异步消费和内部受控调用，不得绕过 Java 报告任务生命周期对外暴露核心业务闭环。
- Higress SHALL 作为本地和生产网关能力候选，外部 `/api/v1/**` 默认路由到 Java 业务核心。
- 本地开发 SHALL 优先通过 Docker Compose 复用或最小化部署 PostgreSQL、Redis、RocketMQ、MinIO、Milvus、OpenSearch、Higress 等依赖。
